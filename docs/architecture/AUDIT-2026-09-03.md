## 2. 类型检查门禁 🔴 **阻塞问题**

### 问题详情

```bash
npx tsc --noEmit
# 输出：Found 537 errors in 76 files.
```

### 错误分布

| 包 | 文件数 | 主要错误类型 |
|----|-------|------------|
| packages/shared | ~25 | implicit any, 解构参数未注解, index signature 缺失 |
| packages/ui-restore | ~30 | 同上 + return type inference |
| packages/ui-reverse-agent | ~21 | 同上 |

### 典型错误模式

1. **implicit any** (最多)
   ```typescript
   // packages/shared/src/antihack.ts:22
   const out = []  // Variable 'out' implicitly has type 'any[]'
   ```

2. **解构参数未注解**
   ```typescript
   // packages/shared/src/dsl-clean.ts:40
   function normalize({ canvas, sections }) {  // 全部参数 implicit any
   ```

3. **缺失 index signature**
   ```typescript
   // packages/shared/src/quota-tracker.ts:55
   this.sessionCooldowns["default"] = ...  // implicit any
   ```

### 影响

- ❌ 违反项目承诺：AGENTS.md 明确"类型 0 错误阻塞 CI"
- ❌ CI 门禁配置存在但**未实际阻塞**（.github/workflows/ci.yml 中有 typecheck job）
- ⚠️ 类型安全性弱化，运行时错误风险增加

### 历史背景

根据 CI 配置注释：
> 类型检查(阻塞门禁): 2026-08-29 起全仓 tsc --noEmit 清零(基线 829→0, 过程见 chore/type-coverage 分支与 doc19)。新增类型错误将直接红 CI。

**但实际未达到 0 错误**，存在 537 个残留。

### 修复建议

**紧急度**：🔴 高优先级（阻塞）

**方案**：
1. 立即修复高频模式（~80%可自动化）：
   - `const arr = []` → `const arr: any[] = []` 或明确类型
   - 解构参数添加类型注解：`function f({ a, b }: { a: T1, b: T2 })`
   - index signature：为对象添加 `Record<string, T>` 或明确字段

2. 配置 `tsconfig.json` 临时 baseline（如需分阶段）：
   ```json
   {
     "compilerOptions": {
       "skipLibCheck": true,
       "noImplicitAny": false  // 临时，逐步收紧
     }
   }
   ```

3. 确保 CI typecheck job **真正阻塞** PR 合并

**预估工作量**：1-2 天（批量模式修复 + 逐文件验证）
